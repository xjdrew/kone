# macOS 管理与网络权限

无参数启动先以普通用户身份打开管理页。用户明确启用接管时，系统才请求管理员授权，启动独立网络助手；浏览器、管理服务和菜单保持普通权限。已有显式配置的 CLI 仍可由用户自行通过管理员终端运行。

网络助手负责 TUN 与本次接管的路由，并复用 KONE 的流量、DNS、诊断和配置快照。配置通过私有 IPC 传递，命令行只有临时通道和父进程标识，不包含代理凭据。双向核验通道的 UID、PID 与可执行文件；临时目录和套接字仅允许所属用户及管理员访问。

创建 TUN 后，助手先把真实设备名称和索引交给管理进程持久记录，得到确认后才配置网络。暂停、退出或管理进程断连，都走同一停止与清理流程；清理失败会保留恢复证据。授权超时后立即关闭本次通道，晚到的助手不能开始接管；原生授权请求未返回时，不叠加新的请求。

macOS 的 DNS 监听使用本机回环入口，例如 `127.0.0.1:53`。UTUN 的点对点地址不能当作本机 DNS 监听地址。启用 `dns.system` 后，助手只创建会话拥有的临时解析服务，正常停止或会话死亡时撤销；物理/VPN 服务保留。管理模式首次默认开启该选项，CLI 默认关闭；加密 DNS 和特殊 VPN/应用解析行为仍有独立边界，见 [系统 DNS 引导](system-dns.md)。

独立 CI 已验证普通用户与管理员子进程的真实私有通道、正常停止和断连清理，并在 disposable macOS runner 上验证 `system`、`mixed` 两种协议栈的真实 UTUN Fake-IP TCP/UDP 往返、端口占用回滚、路由冲突时保留外部路由，以及退出后移除自有设备。系统 DNS 原生用例验证真实查询、晚启动失败、解析会话死亡与原始上游恢复；测试前后确认默认路由和原物理 DNS 保留。运行代码通过内核 PF_ROUTE 的 errno 和应答确认路由变更，删除前重新验证所有权。

这些自动化证据不代替真实管理员弹窗、签名/公证、锁屏唤醒和干净机器安装体验的人工验收。当前开发包仍须遵守 macOS 对未签名应用的信任限制，不会自动安装证书、常驻服务或开机接管。
