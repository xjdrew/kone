# macOS 桌面与权限机制

面向开发者的菜单、权限助手与验收边界；安装和首次启用步骤见 [桌面指南](../user/usage.md#2-首次配置)。

## 网络权限与助手

无参数启动先以普通用户身份打开管理页。用户明确启用接管时，系统才请求管理员授权，启动独立网络助手；浏览器、管理服务和菜单保持普通权限。已有显式配置的 CLI 仍可由用户自行通过管理员终端运行。

网络助手负责 TUN 与本次接管的路由，并复用 KONE 的流量、DNS、诊断和配置快照。配置通过私有 IPC 传递，命令行只有临时通道和父进程标识，不包含代理凭据。双向核验通道的 UID、PID 与可执行文件；临时目录和套接字仅允许所属用户及管理员访问。

创建 TUN 后，助手先把真实设备名称和索引交给管理进程持久记录，得到确认后才配置网络。暂停、退出或管理进程断连，都走同一停止与清理流程；清理失败会保留恢复证据。授权超时后立即关闭本次通道，晚到的助手不能开始接管；原生授权请求未返回时，不叠加新的请求。

macOS 的 DNS 监听使用本机回环入口，例如 `127.0.0.1:53`。UTUN 的点对点地址不能当作本机 DNS 监听地址。启用 `dns.system` 后，助手只创建会话拥有的临时解析服务，正常停止或会话死亡时撤销；物理/VPN 服务保留。管理模式首次默认开启该选项，CLI 默认关闭；加密 DNS 和特殊 VPN/应用解析行为仍有独立边界，见 [系统 DNS 引导](dns.md#系统-dns-引导)。

历史独立 CI 已验证普通用户与管理员子进程的真实私有通道、正常停止和断连清理，以及 `system`、`mixed` 的真实 UTUN Fake-IP TCP/UDP、端口占用回滚、外部路由保留和设备清理。当前 macOS 平台任务将同样的 UTUN/系统 DNS 场景扩展到 `system`、`gvisor`、`mixed`，需按对应 SHA 的实际结果验收，不能沿用历史两栈结果证明 gvisor 已通过。系统 DNS 还覆盖真实查询、晚启动失败、解析会话死亡与原始上游恢复，前后核对物理 DNS/默认路由。运行代码通过内核 PF_ROUTE 的 errno 和应答确认路由变更，删除前重新验证所有权。

这些自动化证据不代替真实管理员弹窗、签名/公证、锁屏唤醒和干净机器安装体验的人工验收。当前开发包仍须遵守 macOS 对未签名应用的信任限制，不会自动安装证书、常驻服务或开机接管。

## 菜单栏入口与验收

打开 `Kone.app` 默认打开管理页面并保留菜单栏图标，不弹终端；`-no-browser` 可静默启动菜单栏。关闭页面后可从菜单栏重新打开管理。终端使用独立的 `kone-cli`。无参数管理启动与启用接管是两个动作，Web profile 不读取项目 `config.toml`；首次需核对 TUN 入站、出站与规则，见 [桌面指南](../user/usage.md#2-首次配置)。管理、浏览器及菜单在普通用户上下文运行，特权数据面通过独立助手和受限制的私有通道控制；菜单不自行配置 TUN、路由或 DNS。关闭浏览器不停止接管，选择退出则交给统一生命周期完成恢复。

菜单使用系统 `/usr/bin/osascript` 的 JavaScript for Automation Objective-C bridge 调用 AppKit，不增加 CGO 或第三方桌面框架。它只创建自己的 `NSStatusBar`、`NSMenu` 与 target/action 对象，不向其他应用发送 Apple Events，也不请求辅助功能权限。实现依据 [Apple 的 JXA bridge 说明](https://devstreaming-cdn.apple.com/videos/wwdc/2014/306xxjtg7uz13v0/306/306_javascript_for_automation.pdf) 和 [NSStatusItem API](https://developer.apple.com/documentation/appkit/nsstatusitem?language=objc)。

Go 父进程通过有界管道发送缓存状态和可用动作；脚本仅能返回“打开管理、启用、暂停、诊断、退出”枚举。凭据、管理令牌、代理 URL 和完整配置不经过该协议。点击动作仍由 Go 控制层处理，原生菜单不直接发网络请求。“诊断”会直接打开管理页的诊断页面，不会自动发起探测。状态未知时不显示已接管，操作按钮按实际状态启停。

脚本实际尝试创建 AppKit 菜单，检查显示环境、状态项和按钮，成功后才发送 `READY`。不因会话属性预先跳过全部图形能力。没有可用桌面时明确返回不可用；GUI 无法维持菜单时显示启动提示并退出，避免留下没有入口的后台进程，CLI 管理可继续使用已有浏览器入口。普通用户启动可尝试菜单入口，管理员进程不创建桌面菜单。

菜单启用或暂停接管失败会显示安全的原生提示并打开 Web 诊断；错误写入有界脱敏运行日志，管理服务保留。成功操作不会强制打开页面。权限助手或流量数据暂不可用与管理连接中断分别显示。

长驻阶段使用 `NSApplication` 事件循环和 `NSTimer` 读取有界状态管道，由 AppKit 管理每轮临时对象。管道 EOF 时停止计时器、恢复描述符标志、移除自己的状态项并退出；输入错误也先完成同样的清理。异常挂起只终止本次创建的子进程，不按名称杀死其他 `osascript`。

原生自测入口 `--self-test` 创建真实 AppKit 菜单，通过 `performActionForItemAtIndex` 验证目标/selector、动作顺序、禁用操作和退出状态，然后移除菜单。没有 WindowServer 时以固定不可用状态退出，不把 headless 跳过当作图形功能通过。Go 测试还检查有界协议、启动超时、异常断连与子进程清理；浏览器验收只证明管理 Web 的交互，不代替 AppKit 验收。

历史原生 macOS CI 已实际通过菜单 selector/状态自测和 UTF-8 状态管道 EOF 清理，两项均未跳过；管理员助手的真实私有通道、正常停止和断连清理，以及当时 system/mixed 的 UTUN TCP/UDP 往返与失败回滚也已通过。可核对 [原生菜单与助手验证记录](https://github.com/xjdrew/kone/actions/runs/41233263296/job/124631668985) 和 [UTUN 验证记录](https://github.com/xjdrew/kone/actions/runs/41233263296/job/124631669146)。当前三栈与合并后的平台任务必须查看新 SHA 的执行结果，不能把旧证据当作 gvisor 验收。权限边界见 [macOS 网络助手](macos.md#网络权限与助手)。

实际鼠标菜单交互、锁屏/唤醒、管理员权限对话框、干净机器安装/升级/卸载仍需带桌面的 macOS 验收。发行包尚未签名或公证，系统信任限制仍然适用；没有自动安装证书、服务或开机接管。
