# 独立连接诊断

诊断只检查你明确指定的端点、协议和本次网络环境，不重放应用的请求，不携带业务凭据，不自动修改规则或启用接管。结果与业务流量统计分开，保留配置版本、时间和有效期；五分钟前的成功不能证明现在仍然可达。

## TCP 与 TLS

TCP 连接成功只说明连接建立。HTTP CONNECT/SOCKS5 的成功应答、代理外层 TLS、代理认证和目标 TLS 是不同阶段。Shadowsocks 流建立没有目标连接成功应答；没有验证目标 TLS 时只记录传输已建立，不据此宣称目标可达。

## UDP：验证 DNS 响应

UDP 没有通用的连接成功应答，向任意端口发出一个数据报不能证明对方收到。诊断页选择 **UDP · 独立 DNS 响应验证** 后，需要重新明确填写一台提供 DNS 服务的服务器，而不是沿用观察到的 QUIC/游戏等业务端点。端口默认 53，可显式修改。

- 查询名称默认 `example.com`，查询类型可选 A 或 AAAA。它们是新建的诊断查询，不复制观察到的业务载荷。
- 服务器地址族与查询类型独立：IPv6 DNS 服务器也能回答 A 查询。直连域名使用引擎固定的系统/私有解析上下文；自动地址族优先 A，无可用 A 时再查询 AAAA。可显式选择 IPv4/IPv6。
- 用域名指定服务器时，其地址解析仍遵循引擎已有的 UDP/TCP DNS 策略；这一步不作为 UDP 探测成功的证据。是否使用 TCP 解析服务器地址，与是否收到被测服务器的 UDP 响应是两件事。
- SOCKS5、Shadowsocks 使用原生 UDP，服务器域名保留代理端解析。通过代理强制服务器地址族时，应输入对应 IP 字面量，因为远端域名解析不提供强制地址族控制。
- HTTP/HTTPS 返回“不支持 UDP”；即使业务规则配置了 `udp-fallback = "direct"`，诊断也不会借直连冒充该代理的 UDP 能力。
- 只有收到能解析、事务 ID、问题名称、类型、类别及响应标志都匹配的 DNS 响应，才记录本次 UDP/DNS 路径可达。原样回显查询、错误 ID 和无关数据不会算成功。
- NXDOMAIN、REFUSED 等响应码和 TC 截断标志单独展示：收到这些有效响应能证明 UDP 往返，但不代表 DNS 查询得到所需答案。UDP 诊断不执行 TCP 重试，也不证明 QUIC 或其他业务成功。
- 超时显示结果未知，不能区分丢包、防火墙静默丢弃和不提供该协议的服务。配置错误、出站能力、名称解析、代理认证/关联、发送和响应验证分别报告。

探测无需创建 TUN；接管运行时复用其真实出口、DNS 快照和配置版本。网络助手运行的数据面也通过同一受保护 IPC 发起诊断，取消单个探测不会暂停业务接管。Fake-IP、自有虚拟网段、组播及未指定地址不能作为可达证明。

## 资源与 API

按需发起，不后台周期探测或扫描网段。每任务最多比较 8 个出站，单出站最长 5 秒，任务总计最长 20 秒；共享操作及探测并发有上限，每分钟最多接纳 32 次出站探测。幂等重试复用原任务，不重复扣预算；结果有界保留，任务可取消。多出站超时时，后面的出站可能未执行，不据此判定其失败。

现有 `POST /api/v1/diagnostics` 默认仍是 TCP；UDP 请求示例：

```json
{
  "target": "[::1]:5353",
  "outbounds": ["direct", "office"],
  "protocol": "udp",
  "udp_mode": "dns",
  "dns_name": "example.com",
  "dns_type": "AAAA",
  "address_family": "ipv6",
  "tls": false
}
```

目标必须是明确的 `host:port`，协议选项严格校验。写操作仍需要管理会话与相应 CSRF 证明；速率超限返回 429。返回任务 ID 后通过操作接口读取结果，不通过重试 POST 猜测任务是否完成。
