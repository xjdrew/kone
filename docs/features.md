# KONE 产品需求与未来规划

状态：需求草案 v1.2，供后续设计、拆分任务和验收使用，不表示相关功能已经实现。整理日期：2026-10-31；现状栏以已合并的 `0ee405d`（sing-tun/Wintun、配置与 UDP 策略迁移）为基线，并行未提交的实现不计为已验收。以后应随实现更新状态与验收证据。

管理页面的页面结构、交互流程、桑基图、表单状态与验收细则见 [管理页面需求文档](management-ui-requirements.md)。

本轮实现、自动化证据与仍需实机验收的边界见 [新特性验收索引](acceptance.md)。下文「现状」保留需求编写时的历史基线，不代表本轮已经实现或尚未实现的最终状态。

本文统一梳理原有「管理界面、惰性代理、简易配置、性能优化、持续发布」及原 `other` 的八项规划，逐项对应关系见第 11 节。用户已确认的补充见第 3.4 节；其余新增首期范围、默认行为、优先级、阶段及标为「建议」的方案/数值仍待产品评审确认，待决策项集中列在第 12 节。

## 1. 要解决的核心问题

**让用户在不破坏原有网络的前提下，只把确有需要的流量交给代理，并且能看清、判断、调整、验证和撤销每一次接管。**

日常使用的障碍是：不知道 TUN 改了什么，不知道哪些流量需要代理，不知道规则有没有生效，出问题时不知道如何恢复。管理界面、诊断、配置、性能和发布都应服务于这个闭环。

| 编号 | 核心问题 | 用户需要得到的结果 |
| --- | --- | --- |
| P01 | 接管有风险：错误路由、DNS、自循环可能破坏上网 | 接管前检查，失败不留下半配置，随时停止并恢复 |
| P02 | 接管不透明：域名、IP、协议、规则与实际出站混在一起 | 首页用桑基图看清入站到最终目的的流向，并能解释和钻取 |
| P03 | 规则维护靠猜：难以提前列出所有需要代理的目标 | 从已观察失败发现候选目标，用有限诊断帮助判断 |
| P04 | 修改成本高：手改配置、重启、猜测是否生效 | 小范围一键设置，明确反馈，验证新连接，支持撤销 |
| P05 | 协议与解析环境复杂：TCP 能用不代表 UDP、IPv6、内网能用 | 能力边界明确，局域网、企业 DNS、VPN 不被误伤 |
| P06 | 排障证据不足：汇总流量解释不了当前连接和失败 | 实时状态、失败阶段、DNS 记录与可靠的归属信息 |
| P07 | 观察可能代价过高：统计、探测、日志增加开销 | 非必要流量少处理，后台任务有资源与隐私边界 |
| P08 | 交付门槛高：编译、配置文件、驱动、权限、恢复依赖经验 | 桌面无需指定配置即可打开，在管理界面完成配置和生命周期操作 |
| P09 | 长期质量不确定：协议、数据与版本持续演进 | 用兼容矩阵、测试、性能基线和可追溯发布控制变化 |

## 2. 现状与规划的区别

以下事实来自仓库，不是未来功能已经完成的声明。

| 领域 | 已有能力 | 缺口与依据 |
| --- | --- | --- |
| 数据路径 | sing-tun 提供 TUN 与透明 TCP/UDP 会话；支持 Fake-IP/显式 CIDR 选择性接管、可选全 IPv4 捕获及 LAN 客户端；TCP 经内置 `direct`/`reject` 或 HTTP、HTTPS CONNECT、SOCKS5 出站 | 全捕获仍遵守既有更具体路由，不等于双栈/任意协议支持；旧报文/NAT/relay 已删除；见 [架构](architecture.md)、[stack.go](../pkg/kone/stack.go)、[flow.go](../pkg/kone/flow.go) |
| 出站绕过 | 代理端点名称有直连例外；配置真实出口后，代理外层、直连和上游 DNS 绑定物理接口，回环代理/DNS stub 保留回环路径；全捕获和 CIDR 默认捕获要求指定出口 | 出口改变需重启，自动换网与更广控制流量的绕过仍需后续设计/验收，不能把已有接口绑定当成全部未来场景完成；见 [outbound.go](../pkg/kone/outbound.go)、[配置说明](configuration.md) |
| UDP | 内置 `direct` 直连、`reject` 拒绝；现有代理仅支持 TCP，UDP 默认拒绝，仅允许显式 `udp-fallback = "direct"` 或 `"reject"`；能力检查先于真实目标解析/拨号，已有会话保留原快照 | 没有 SOCKS5 UDP ASSOCIATE；不能说「HTTP 不支持 UDP，所以除 53 外 UDP 不受影响」；见 [outbounds.go](../pkg/kone/outbounds.go)、[flow.go](../pkg/kone/flow.go) |
| DNS | A 查询参与虚拟地址决策，其他类型转发；上下游目前均用 UDP；上游并发查询 | 缺 DNS TCP/截断回退、全查询历史和分流；见 [dns.go](../pkg/kone/dns.go) |
| IPv6 / 包处理 | 可配置 IPv6 上游 DNS 地址，但不接管 IPv6 流量；system/mixed 栈接管透明会话与报文处理，Fake-IP 地址池及 CIDR 使用 `net/netip` | 包/分片行为按选定栈验证，不继承旧 filter 的 ICMP/分片结论；IPv6 DNS 上游不等于 IPv6 代理，ping 虚拟地址不证明目标服务可达；见 [架构](architecture.md)、[stack.go](../pkg/kone/stack.go)、[dns_ip_pool.go](../pkg/kone/dns_ip_pool.go) |
| 管理与统计 | HTML 汇总/列表/详情、DNS 映射、脱敏配置、POST reload | TCP 转发结束后才记账，UDP 未接入同样统计；不是实时带宽、桑基图或全机观察；见 [manager.go](../pkg/kone/manager.go)、[flow.go](../pkg/kone/flow.go) |
| 配置 | 严格 TOML；`[[outbounds]]` 以 `name`/`url` 声明代理及可选 UDP 回退，内置 `direct`/`reject` 无须配置；可选 `[dns]` 默认发现系统上游；规则/出站原子热更新 | 已移除旧 relay/NAT 端口字段；旧连接保留原出站；核心/DNS、管理地址或 CIDR 捕获变化需重启；桌面无文件配置仍是需求；见 [配置说明](configuration.md)、[示例](../configs/kone.example.toml) |
| 恢复 | 启动失败回滚、正常退出恢复自有变更、关闭会话 | 强杀/断电恢复、持久恢复记录、换网恢复待实现；见 [运行可靠性](runtime.md) |
| 平台与交付 | Windows 使用内嵌 Wintun，不需单独安装 TAP；Linux TUN、macOS utun；普通构建 system，`mixed` 需 `with_gvisor`；CI 覆盖三平台 race、system/mixed、Windows 真实 Wintun、Linux 网关及七个二进制目标（含 ARMv7） | 缺桌面、普通用户安装体验与自动 Release；macOS 特权行为和真实部署性能仍需验收；见 [Windows 说明](windows/README.md)、[运行可靠性](runtime.md)、[CI](../.github/workflows/go.yml) |
| 性能、数据与许可 | GeoIP 仍为内嵌旧数据，已有 GeoIP benchmark 未按测试框架迭代计量；KONE 使用 GPL-3.0-or-later，sing-tun 为固定的外部 fork 模块，保留各组件许可及 Wintun 二进制许可 | 需建立新数据面的有效性能基线和 GeoIP 更新机制；发行继续携带对应源码与许可说明；见 [GeoIP 测试](../pkg/geoip/geoip_test.go)、[依赖与修补](sing-tun.md)、[LICENSE](../LICENSE) |

必须澄清三个概念：

1. **选择性接管与可见性。** 用户已接受未进入 KONE 的流量不可观察，本需求不要求全机旁路观察。进入 KONE 的 DNS 请求可以记录，但不能据此断言后续业务连接也进入了 KONE；查询 DNS 不代表建立连接。
2. **进入 TUN 与使用上游代理。** 进入 TUN 后可能 DIRECT、REJECT 或失败，界面分别显示路径、期望策略和实际结果。
3. **失败与应该代理。** DNS、目标服务、认证、TLS、换网都可能造成失败；探测提供证据，不直接断言必须代理。

## 3. 产品原则、范围与闭环

### 3.1 原则

- 最小接管：以保持非必要流量原路径、只接管明确选择的目标和受支持协议为目标；DNS 虚拟地址造成的跨协议影响必须在启用前说明并校验，不能承诺无法兑现的协议隔离。
- 安全优先：自身外层出站不回流；改变系统网络前完成配置、能力和冲突检查。
- 解释充分：汇总 → 分类列表 → 详情逐层深入；状态包含原因、时间与适用范围。
- 操作可验证：区分保存、应用与连接结果；失败可恢复，成功可撤销。
- 资源有界：不依赖无限扫描、无限历史或全量包处理实现透明。
- 复用核心：先演进管理 Web，Windows/macOS 桌面提供入口与生命周期管理，CLI 继续可用。
- 桌面零文件配置：Windows/macOS 使用统一默认配置启动，在管理界面维护入站、出站、规则与 DNS；不要求用户查找或指定配置文件。
- 流向优先：首页以桑基图作为进入 KONE 的流量总览，兼顾美观、准确和逐层钻取。

### 3.2 「惰性代理」的工作定义

按原文「一键设置代理」解释为：**默认尽量直连 → 发现已观察失败 → 按需诊断 → 用户选择精确目标代理 → 验证新连接 → 保留或撤销规则。**

这不要求每次业务先失败再切换，也不重放业务请求。已配置代理规则的流量直接按规则执行。自动新增规则、自动切换出站另行决策，首期不默认开启。

### 3.3 用户与场景

首要用户是在 Windows/macOS 使用已有代理的个人用户；兼顾企业内网/VPN 使用者，以及 Linux、树莓派、容器 CLI 和已支持的 Linux 网关用户。支持同一所有者授权手机/平板浏览器访问 KONE 主机、查看流量与页面效果；不要求手机安装 KONE 内核，也不因此接管手机全部流量。管理界面首期不承担网关 forwarding/DHCP/防火墙的自动部署；多用户远程管理平台不作为默认产品形态。

| 场景 | 期望过程 | 结束条件 |
| --- | --- | --- |
| S01 首次使用 | 安装 → 无参数打开应用 → 自动加载默认配置 → 管理界面维护入站/出站 → 预检并启用接管 | 无配置文件、无可用代理、未安装驱动或未提权时仍能打开管理界面；接管前再检查必要条件 |
| S02 网站不可达 | 已观察目标进入候选列表 → 查失败阶段 → 对比直连/代理 | 得到带时间、协议范围的证据 |
| S03 一键代理 | 选目标/出站 → 预览影响 → 应用规则 → 独立验证 | 能看新连接命中、验证结果及撤销入口 |
| S04 流量异常 | 首页桑基图 → 点击入站/规则/出站/目的或连线 → 筛选列表 → 连接详情 | 看清实际路径，区分长连接、代理故障、规则错误和未知归属 |
| S05 企业网络 | 内网名称交给所属 DNS，局域网按预期直连 | 不泄漏内部名称，不破坏原 VPN 访问 |
| S06 休眠或换网 | 检测出口变化 → 重查 DNS/绕过/冲突 → 恢复或停用 | 不继续使用失效路由并声称正常 |
| S07 暂停或退出 | 停止接管 → 关闭会话 → 恢复自有变更 | 显示恢复结果，失败提供恢复办法 |
| S08 升级或异常结束 | 校验版本/配置 → 正常升级；下次启动检查遗留 | 保留配置，遗留变更不被盲目覆盖 |
| S09 手机访问 | 主机显式开启局域网访问 → 手机浏览器授权 → 响应式首页/桑基图 → 触控钻取 | iOS/Android 真机可查看实际主机数据，布局可读，未授权不可查看，手机页面关闭不停止主机 |

### 3.4 用户已确认的产品决策

1. **Windows/macOS 无需指定 config 文件。** 首次启动使用统一内置默认配置，先让管理界面可用；日常通过界面配置入站、出站等内容。默认配置是初始化基线，后续启动自动读取应用管理并持久保存的用户设置，不在每次启动时重置。统一指配置模型、校验与默认行为一致，允许平台存储位置不同。Linux/独立 CLI 保留显式配置能力。
2. **观察范围止于 KONE。** 不要求观察未进入 KONE 的业务流量，不为补齐全机统计强制接管更多流量。进入 KONE 的 DNS、业务连接、主动诊断与内部控制流量分别统计，不根据 DNS 查询推测未观察的连接。
3. **首页采用桑基图（Sankey Diagram）。** 优美、直观地展示进入 KONE 的流量经过的可观察结点及最终业务目的；图形是首页主要总览，列表和详情承担进一步排障。
4. **支持手机和平板访问。** 复用管理 Web，响应式适配移动浏览器，首页保留可触控的桑基图。手机通过主机显式开启并授权的局域网入口访问；默认本机回环及隐私边界保留，普通远程访问不自动开放。

打开应用不等于启用系统网络接管。默认配置应能启动本地管理与托盘；缺少可用出站或接管条件时展示待配置/待启用，不自动进行无效全局接管。应用升级保留用户设置，恢复默认必须是显式动作。

## 4. 路径与协议能力契约

### 4.1 路径分类

| 路径 | 含义 | 允许声明的观察能力 |
| --- | --- | --- |
| 系统直连，未进 TUN | 系统按原路由连接目标 | 可能仅有 DNS 观察；无证据时不提供连接带宽/进程/成败 |
| 已进 TUN，DIRECT | 经 KONE 再直接连真实目标 | 可统计该路径，不标为使用上游代理 |
| 已进 TUN，代理出站 | 经选定上游连接目标 | 展示规则、出站、握手/连接结果和流量 |
| 已进 TUN，拒绝或失败 | 策略拒绝、能力不足、解析/连接失败 | 展示阶段与原因；零字节失败也保留事件 |
| KONE 控制流量 | 代理外层连接、DNS、探测、更新等 | 单独分类；外层连接避免递归，不混入业务总量 |

域名、IP、协议、端口是不同维度。「某 IP 已代理」不等于该 IP 的所有域名和协议均代理。虚拟地址与真实地址分开显示；实际目标地址不可得时明确说明，不把代理端点地址冒充目标。

### 4.2 协议能力

| 能力 | 首期要求 | 扩展条件 |
| --- | --- | --- |
| IPv4 TCP + HTTP/HTTPS CONNECT/SOCKS5 | 保持现有能力与真实出口绑定，补管理解释、诊断及更广场景验收 | 到上游的 TLS 和目标应用 TLS 分阶段解释 |
| UDP 业务 | 保持现有内置直连/拒绝及代理默认拒绝、显式 `direct`/`reject` 回退；未导入 TUN 的流量不声称已观察，已进 TUN 的能力不足在界面明确提示 | 完整 UDP 代理须验证往返、超时、统计、MTU；不能因 SOCKS5 名称就声明 UDP 支持 |
| 无能力回退 | 不把要求代理的流量静默改为 DIRECT | 直连回退必须显式配置，记录实际回退及范围 |
| DNS UDP/TCP | DNS 接管产品化前支持两种传输及截断回退 | 解析路径、内网分流、取消均可验证 |
| IPv6 | 明示未覆盖范围，不宣称完整双栈接管 | 地址、规则、DNS、路由、转发、绕过、恢复全链路通过 |
| ICMP / 分片 / 其他协议 | 公布支持或丢弃策略及诊断限制 | 不把本地 ICMP 应答当远端证据，不承诺任意协议透明代理 |
| Shadowsocks（SS） | 保留后续出站需求 | 明确版本、加密方法、TCP/UDP、互操作、安全和许可范围 |

虚拟 IP 按名称分配而非按应用协议分配。只有 TCP 能力的出站仍可能遇到应用访问同一虚拟 IP 的 QUIC/UDP。保留原文「除 DNS 外非必要 UDP 尽量不受影响」的兼容目标：启用域名虚拟地址前，必须明确同域名 UDP 的实际路径及影响。若保持原路径是该模式的硬要求而平台无法实现，应拒绝启用该模式；显式直连回退或拒绝属于需要说明兼容代价的另选策略，不能靠隐藏 UDP 或声称它未受影响规避需求。

## 5. 功能需求与验收标准

P0 是接管和写操作的安全前提；P1 是日常使用闭环；P2 是扩展能力。不要求同一版本完成全部需求，阶段见第 10 节。

### 5.1 安全接管与恢复

| ID / 优先级 | 需求 | 验收标准 |
| --- | --- | --- |
| SAFE-01 / P0 | 接管预检：配置、平台/驱动、权限、端口、网段、路由/DNS/VPN 冲突，预览系统变更 | 阻断项失败不进入运行态，不留下本次变更，错误指出原因和下一步 |
| SAFE-02 / P0 | 完整出站绕过：保护代理外层及 DNS、探测、更新的外层系统连接，覆盖 IP/域名端点、多地址和地址变化 | 代理 IP 被代理 CIDR 覆盖仍不成环；reload/换网仍成立；控制流量按指定出站执行且外层不递归；无法安全绕过时拒绝相关接管 |
| SAFE-03 / P0 | 本地控制与紧急停用：代理故障、业务 DNS 失败不阻断管理；暂停/退出复用可靠停机路径 | 上游不可用仍可管理；暂停恢复自有路由/DNS并关闭会话，管理入口保留；恢复前重新预检 |
| SAFE-04 / P1 | 异常恢复：持久记录最小自有变更，检测崩溃遗留与休眠/出口/DNS/VPN/接口变化 | 强杀后下次启动可检测并修复遗留；只操作可确认所有权的资源；外部新修改不盲目覆盖；失败明确报告 |

复用现有 [生命周期与所有权](runtime.md)，恢复记录不含凭据。当前管理服务与引擎一起关闭，暂停后仍可管理需要引入持续存在的本地控制层，不能只调用现有 Close 后假定管理口仍在。暂停、重启、撤销规则须考虑应用已缓存的虚拟 IP；不能假定刷新系统 DNS 就清除全部应用缓存。具体缓存兼容/过渡策略在 DNS 与停机设计中验证。

### 5.2 规则与一键操作

| ID / 优先级 | 需求 | 验收标准 |
| --- | --- | --- |
| RULE-01 / P0 | 可解释决策：规则有稳定 ID、来源、顺序；展示命中规则、版本、期望/实际出站、保护例外与回退 | 连接可追溯决策，模拟与新连接一致；安全绕过优先于用户接管规则且可解释 |
| RULE-02 / P1 | 一键精确代理：选择域名/IP、协议范围和出站，默认最小作用域 | 默认精确域名，只有 IP 时默认单地址；扩大后缀/CIDR 前预览影响；不因共享 IP 改其他域名策略；重复/冲突有提示 |

首期遵守已有热更新边界。CIDR/核心设置需重启时明确提示，不把保存当生效；在线路由更新须另有原子应用与回滚设计。协议/端口筛选若尚不支持，不能创建看似精确、实际扩大到全部协议的规则。配置发布失败保留旧快照，探测失败也不能误报配置未应用。

### 5.4 观察、统计与进程

| ID / 优先级 | 需求 | 验收标准 |
| --- | --- | --- |
| OBS-01 / P0 | 仅统计进入 KONE 的可观察流量，区分 DNS、TUN/其他入站、活动连接和主动探测，显示未知/过期/截断 | 不要求补齐全机旁路流量；无连接证据不显示虚构流量/成功率；页面明确范围；DNS 事件不当成功连接 |
| OBS-02 / P1 | 活动与失败记录：协议/端口、目标、阶段、出站、规则、时间、错误、版本 | 长连接结束前可见；零字节失败可查；按时间/目标/协议/出站/状态筛选，稳定分页排序 |
| OBS-03 / P1 | 实时速率/累计：域名、IP、协议、出站、整体上下行 | 长连接增量更新；TCP/UDP 按实际支持范围计数；维度不互相相加；明细满额不影响独立整体计数，并提示缺失 |

统计约定：上下行从客户端视角；默认按业务转发载荷计数，IP/TUN 包字节和上游开销如提供则单列。速率为明确采样窗口内增量，注明窗口、时间和单位。默认累计以本次引擎会话为界，暂停/恢复、重启产生新会话标识；未实现跨会话历史就不显示历史累计。

域名归属说明来源（虚拟 IP、已观察 DNS、用户输入等）。共享 IP、一域多 IP、CNAME、过期缓存中无法确定时标未知/候选，不依靠时间相近强行归因。

### 5.5 连通性诊断

| ID / 优先级 | 需求 | 验收标准 |
| --- | --- | --- |
| DIAG-01 / P1 | 诊断已观察或用户指定目标，区分解析、连接超时/拒绝、代理握手、认证、可选 TLS/应用错误 | 记录目标、解析路径、协议/端口、出站、网络上下文、时间；直连/代理对比注明解析差异；TCP 成功不当应用成功 |
| DIAG-02 / P1 | 失败候选靠前，一键代理/复测；至少有未知、待测、可达、失败、过期、不支持 | 直连失败代理成功才给有范围的建议；两边失败分别解释；旧结果降级；探测不自动改规则 |
| DIAG-03 / P0 | 探测副作用有界：默认按需，周期探测可关闭；限并发、速率、超时、退避、去重、可取消 | 不扫描未发现网段；不重放 POST/登录/支付，不携业务凭据；fake-IP ping 不作远端证据；探测流量独立计量 |

「不可达」绑定协议/端口和时间，例如 `TCP/443` 当前直连超时；一次 ping 失败不能推断域名整体不可用。内部目标使用所属 DNS 与出口，不为了对比把内部名称发到公共解析器。

### 5.6 配置与管理界面

| UI-05 / P1 | 手机/平板响应式支持，八个主页面可在移动浏览器查看；桑基图支持点选、高亮、展开与钻取 | iOS Safari/Android Chrome 真机横竖屏通过；320 CSS 像素以上可用，无主体横向溢出；不用悬停作为唯一交互，不强制横屏，不默认移除桑基图 |
| UI-06 / P0 | 局域网移动访问须由主机所有者显式开启，有认证、受保护传输、会话权限和撤销；默认回环保留 | 可获得不含长期秘密的访问地址；未授权不读取流量；建议移动默认只读、管理显式授权；关闭/撤销后数据访问和订阅失效；不自动暴露公网 |

保存与运行发布是两个带版本的步骤：保存成功但应用失败时，保留旧运行快照，展示持久版本与运行版本的分歧并提供回退入口；进程异常或重启后也不能绕过预检，把上次应用失败的候选静默视为已确认配置。

统一默认配置不限制以后修改入站/出站；内置默认值只用于首次初始化及显式恢复默认。入站类型仅列已实现能力，首期至少覆盖 TUN，不由「可管理入站」推导必须新增全部 HTTP/SOCKS 入站。按类型显示设备/监听地址、端口、网段和协议范围；出站包含 DIRECT、REJECT 与支持的代理类型。高级 TOML 导入/导出/编辑是可选能力，不进入桌面首次启动的必经流程；CLI 的配置参数不成为桌面使用前提。

Web、桌面、CLI 复用管理契约，包含 API 版本、能力、结构化错误、请求标识、并发修改检测。轮询/推送不限实现方式，断线后重读一致快照。默认仅本机回环；已确认支持所有者显式开启受保护的局域网手机访问，授权、权限和撤销须与响应式页面一起交付；公网远控不在首期范围。

| 版本 | 版本、源码 SHA 或数据来源、校验、兼容范围、构建/更新时间、安装/回退说明 |

桌面控制层至少区分初始化默认配置、管理可用、待修复配置、退出中；数据面区分待启用、预检中、启动中、运行、降级、暂停中、已暂停、停止中、恢复失败。默认配置已加载但未接管属于正常可管理状态。暂停保留管理，退出关闭管理和引擎；无法保证接管安全时停止恢复，不只换状态颜色。

### 6.3 首页桑基图的展示契约

主路径从左到右：**入站 → 命中规则/策略 → 实际出站 → 最终业务目的**。已识别的应用/来源可作为可展开的起始层；实际支持且能观察到的代理链可展开出站层。规则是逻辑决策结点，不是物理网络跳点；不凭配置推断未经过的代理，也不虚构公网中间路由。

| 方面 | 需求与边界 |
| --- | --- |
| 流向证据 | 从同一连接/流的完整路径事实聚合，不拼接互不关联的维度统计制造不存在的路径；DIRECT 保留为实际出站，期望策略与实际回退不同须可解释 |
| 最终目的 | 优先使用有证据的目标域名，详情列出可得真实 IP/端口及来源；无域名则用 IP；远端解析不可得时标明未知，不能用代理端点冒充业务目的；连接失败时标目标为尝试目的而非已抵达 |
| 宽度与指标 | 默认展示当前采样窗口的上下行合计速率，可切换上传/下载或本会话累计字节；每张图统一窗口、单位、样本范围及载荷口径；流向表示逻辑路径，下载模式不把它误称为单向上行包流 |
| 计量一致 | 同一业务量在每一层投影一次，不将各层边权累加为首页总量；同名规则/出站有稳定 ID；快照窗口一致且注明当前配置版本，每条路径保留连接自己的决策版本 |
| 高基数 | 默认突出主要路径，低占比目标合并为可展开的「其他」；规则/出站仍可识别，未知单列；合并后保持同口径总量和路径关联，不能把截断当作零流量 |
| 失败/拒绝 | 已有真实字节按实际统计；零字节失败/拒绝用事件数、状态标记及入口呈现，不伪造正流量线宽；DNS 查询/探测/更新等控制流量另列或显式切换，不混入默认业务图 |
| 交互 | 悬停结点/边高亮完整关联路径，显示名称、指标、占比及状态；点击钻取连接列表/详情，继承时间、入站、规则、出站、目标等过滤；提供返回和清除筛选 |
| 实时稳定 | 长连接持续更新；稳定结点顺序和颜色，避免每秒重排闪烁；支持暂停图形刷新以便检查，暂停图形不等于暂停接管；断连/过期显示数据时间，不继续模拟流动 |
| 美观与可读 | 留白充足、曲线平滑、颜色克制且含义稳定；标签不重叠，长名称省略后可查看全名；手机保留桑基图，点选代替悬停，允许局部平移/缩放并提供等价列表；动效轻量，可降低/关闭，不只靠颜色 |
| 空态与范围 | 无进入 KONE 的业务流量时解释空态并给配置/检查入口，不填充真实感假数据；未进入 KONE 的业务流量不画在图中，也不标为零或已直连 |

桑基图是业务流量在 KONE 中的逻辑路径视图，不是互联网物理路由追踪，也不替代连通性验证。质量验收同时检查美观、量值与路径真实性，不能仅以图表能渲染作为完成条件。

## 7. 隐私、资源与体验约束

- 采集与诊断在 KONE 主机完成，不默认上传域名、IP、进程或业务数据到云端；所有者授权的手机会话只读取权限允许的数据，不记录载荷、业务 URL 查询、认证头、代理密码。
- DNS/连接/探测事件有记录开关、容量、保留策略、清空与脱敏导出。默认有界内存，跨重启持久化另行启用；聚合也说明范围与重置条件。
- 状态不只靠颜色，主要动作可键盘操作，小窗口能完成首次配置与停用。
- 采样、队列、探测、进程查询、列表查询分别限额；耗尽优先保证转发正确，暴露丢弃/截断。

以下为建议验收起点，需在对应任务中确认并实测，不能宣传为已有能力：

| 项目 | 建议起点 | 测量方法 |
| --- | --- | --- |
| 实时反馈 | 按 1 秒窗口采样，正常本地条件下 2 秒内可见 | 长连接传输时对比计数与界面时间 |
| 动作反馈 | 立即显示处理中，最终区分应用/验证 | 慢保存/握手、失败、重复点击注入 |
| 资源稳定 | 表/队列不超声明上限，清理后无持续增长 | 固定负载和高基数长时测试，任务预先固定预算/时长 |
| 性能回退 | 先有有效基线，改动前约定吞吐/开销/回退预算 | 同环境多轮比较，不用共享 CI 单次时延定论 |
| 正常恢复 | 沿用现有默认 15 秒清理预算，超时/失败报告并继续其他清理 | 故障注入和三平台特权验收；不承诺强杀时即时恢复 |

## 9. 设计约束与非目标

- 沿用 Go 1.27.3、`cmd/`/`pkg/`、`gofmt`、`log/slog`、严格 TOML 与生命周期契约。
- Web/桌面不各造规则引擎；不把未确认的框架、数据库、驱动、包处理库写死为产品前提。
- 首期不做完整协议分析、HTTPS 解密、全网扫描、无限审计、多租户远控或节点订阅平台。
- 不要求观察未进入 KONE 的流量，不为首页补图强制扩大接管；不在无 UDP/IPv6 能力时承诺全协议接管。
- 不自动重放失败请求，不默认自动新增永久规则，不静默把代理失败改直连。
- 新依赖/底层替换审查维护状态、平台兼容与 GPL-3.0-or-later 许可要求；保留原始许可和二进制对应源码，Wintun 遵守其预编译二进制许可；技术方案分阶段另行记录。

依赖顺序：先绕过再扩大接管；先统计口径再实时 UI；先诊断证据再推荐代理；先配置/版本契约再桌面；先 DNS 分流/恢复再默认改系统解析；先验证协议全链路再启用对应接管。

## 12. 待决策项与草案默认值

这些不阻止基础安全/数据契约工作，但相应实现启动前须明确记录决策及验收变化。

| 决策 | 草案建议 | 影响 |

| 默认 DNS 的范围/时点 | 简易模式通过预检和内网验收后启用；保留高级手工模式 | 系统 DNS 设置和强制重定向覆盖不同 |
| 临时规则失效 | 建议默认持久，提供显式临时选项并注明失效点 | 按会话/时长需处理虚拟 IP 缓存和旧连接 |
| 历史保留/诊断预算 | 默认有界内存；条数/时长/速率实测确定 | 任务须有默认值、上限、耗尽行为 |
| 桌面与驱动路线 | 复用 Web、隔离特权，框架/驱动单独验证 | 包体、授权、分发、许可、平台矩阵 |
| 移动访问技术细节 | 手机/平板支持已确认；建议默认只读，所有者可授予管理；待固定最低浏览器版本、传输保护/信任和配对方案 | 不再讨论是否支持手机，只确定如何在真实移动浏览器安全可用地访问 |
| 每提交发布粒度与通道 | 建议逐 CI 成功 master SHA 开发预发布，显式版本标记稳定版 | 一次 push 多 commit 是逐个还是只 head 待确认；不可擅自缩减原意 |
| 签名/公证/自动更新 | 普通发行前确定签名/公证；自动安装更新另期，保留手动升级 | 渠道/凭据/预算；未签构建不等同完整安装体验 |
| SS/IPv6/UDP 范围和顺序 | 按实际网络需求独立排期 | 每项指定协议/服务端/平台测试矩阵 |

评审后为各项维护「已确认 / 待设计 / 实现中 / 已验收 / 延后」与任务/PR 链接；已验收附平台和测试证据，延期保留原意与未覆盖边界。
