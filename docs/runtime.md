# 运行可靠性

## 生命周期与资源所有权

管理服务与流量接管分别拥有生命周期。无参数启动先提供管理界面，默认暂停接管；接管失败、暂停或恢复期间仍可查看状态、修复配置和重试。保存配置不等于应用，应用成功也不代替真实业务验证。

数据面 `FromConfig(cfg, options...)` 只校验和构造对象。`Run(ctx)` 是一次性生命周期：创建设备、配置接口和路由、绑定所有监听端口，确认 DNS 就绪后才启用已选择的系统 DNS 引导，随后启动服务并关闭 `Ready()` 通知。任一步骤失败都会返回错误并清理本次数据面资源；管理服务保留。

取消 context、调用 `Close()`、收到 SIGINT/SIGTERM 或任一组件意外退出，都会停止接收连接、取消 DNS/代理握手、关闭并等待 TCP/UDP 会话，再逆序恢复网络、关闭设备并等待所有工作协程。
`Close()` 可以并发、重复调用；引擎实例不支持重新启动。清理使用独立的 15 秒 context，不会继承已取消的运行 context；可用 `WithShutdownTimeout` 调整。
恢复失败会与原错误一起返回，CLI 以非零状态退出，不能将其报告为恢复成功。

## 平台恢复范围

- Linux/macOS：只接管新建设备，拒绝修改已经存在的同名接口。只删除成功添加的路由，关闭自有设备。
- Linux 可显式开启 `dns.system`：仅在已使用 systemd-resolved stub 的系统中管理本次 TUN link 的 DNS/域路由，退出先恢复引导，再关闭 DNS 监听；不改写 `resolv.conf` 或物理/VPN link。
- macOS 可使用会话拥有的临时 DNS 服务；不覆盖物理/VPN 服务。正常退出先撤销并确认系统选择已恢复；解析会话异常退出自动撤销临时值，同时触发引擎停止。CLI 默认关闭，管理模式支持平台首次默认开启，具体前提及边界见 [系统 DNS 引导](system-dns.md)。
- Windows：创建自有 Wintun 网卡，拒绝复用同名现有网卡。记录并恢复 IPv4 DNS 静态/自动模式、DHCP、MTU、metric 与自动 metric，仅移除本次添加的地址和路由，再关闭网卡。启动前明确创建限定于当前程序和自有 TUN 地址的 TCP 防火墙例外；失败进入回滚，退出移除本次规则，已有同名规则保留。
- Linux/Windows 的 IPv6 接管均需显式配置 ULA 虚拟网段，默认关闭；IPv6 地址、监听和路由与 IPv4 分别校验并按所有权清理。macOS 当前明确拒绝启用 IPv6 接管。
- 监听失败时已绑定的端口全部关闭；清理途中单个逆操作失败不阻止其余逆操作执行。

强杀、进程崩溃和系统断电无法保证执行这些逆操作。管理模式记录最小所有权日志和运行代次，重开后展示遗留检测与恢复结果；仅处理能够核实的自有资源，无法确认时保留原状态并要求本机处理，不按接口名称猜测后删除。检测到外部网络变化会暂停接管，管理员确认后再启用。网关管理员配置的 forwarding、DHCP、NAT 与防火墙不属于 KONE 的恢复范围。

## sing-tun 边界

生产数据面只使用 sing-tun 的 system 或 mixed 栈；KONE 负责设备/配置/路由所有权、出站连接和生命周期。使用外部配置模式，避免 sing-tun 自动路由与 KONE 的逆操作相互覆盖。旧报文分发、NAT、relay API 与兼容端口配置已移除。
所有 stack 读包经过故障上报适配器，终止性读写错误会交给 Run 退出；正常关闭的读错误不会重复报告。清理会停止接收新流、取消拨号、关闭活动 TCP/UDP、关闭 stack、逆序恢复网络并关闭设备，最后等待已进入的 I/O 和处理任务。
打开失败时检查普通 nil 和接口中携带的 typed nil，保留原始驱动错误；有效的部分资源仍被清理。system forwarder 的保留地址不参与 Fake-IP 分配。
full capture 添加两条半网 IPv4 路由；真实出口接口绑定应用到代理、直连和 DNS，并跨规则热更新保持不变。Windows 使用 on-link 路由，而不是旧 TAP 的虚拟下一跳。

## 并发与热更新

规则、代理定义、配置和版本号作为不可变对象一次发布。每个 DNS 请求与新 TCP/UDP flow 只读取一个版本，DNS 查询与代理握手不会持有全局规则锁。
更新中的无效规则或需要重启的设置不会改变当前版本。快照 API 返回独立副本；已有连接继续使用创建时的代理，新连接使用新定义。

虚拟 IP 映射保持稳定，策略按读取的规则版本计算。直连 DNS 缓存带版本，旧查询在 reload 后完成也无法覆盖新策略。
sing-tun 管理透明 TCP/UDP 会话；KONE 流处理器同步活动连接及关闭状态，关闭时拒绝发布新连接并等待工作任务。先判规则，再检查出站能力；SOCKS5/Shadowsocks 可使用原生 UDP，HTTP/HTTPS 代理不支持 UDP 时默认拒绝，只有显式配置的回退出站才会接手。`reject` 与禁用出站不触发回退，已建立会话继续使用原快照。

管理统计统一记录 TCP/UDP 业务载荷、零字节失败与会话状态，DNS/诊断单独计量；累计值不当作速率。有界明细、采样窗口和游标会明确报告淘汰/截断，不能用新的记录替换旧样本中的缺失证据。DNS 历史与缓存分别按容量和过期配置管理，活动 Fake-IP 映射保留到持有流结束。

本机进程归属是异步、尽力而为的 IPv4 元组匹配，校验连接与进程启动时间，避免错误归属；远端 LAN、权限不足、复用竞争与尚不支持的元组标为远端或未知，不阻塞转发。它不是全系统应用流量采集。

Windows 托盘和 macOS 原生菜单复用控制层状态与动作，关闭浏览器不会暂停接管，退出必须等待清理。macOS 的普通用户菜单进程和提权助手相互隔离；无桌面会话或原生入口失败时保留管理 Web，详见 [macOS 桌面边界](macos-tray.md)。

## 验收

- 普通单元测试：端口占用、部分配置/路由失败、启动中取消、组件读失败、并发关闭、清理错误、快照一致性、DNS/HTTP/HTTPS/SOCKS5 挂起请求的取消。
- 三平台 race：并发 reload、DNS、管理统计/页面与生命周期。
- `test/integration/lifecycle_linux_test.go`：通过隔离网络命名空间测试真实 TUN、已有路由保护、路由部分成功后的回滚、DNS→TUN→代理 HTTP 流量、代理热更新和 CLI SIGTERM。
- 网关验收使用独立 LAN 客户端和上游命名空间，覆盖 Fake-IP/literal TCP、UDP、REJECT、全局捕获、物理出口绕过和默认路由恢复；system/mixed 分别运行。
- Windows 配置恢复与防火墙所有权使用注入命令的测试覆盖，并在 CI 执行真实 Wintun 启动、端口占用回滚和退出验收；macOS 特权验收仍需另行执行。

`WithNetwork` 与 `WithSockets` 提供可注入的系统边界，供嵌入使用和无特权故障测试；生产 CLI 没有测试专用开关。
